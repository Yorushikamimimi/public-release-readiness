# 公开前检查清单

只检查获授权目标。对每类写“已查 / N/A（理由） / 未查（原因）”；目录存在、已忽略或工具无发现都不自动证明正文安全。必要覆盖无法完成时给 HOLD，或缩小到可检查的干净导出。

## 发布内容与历史

| 范围 | 要检查的内容 |
|---|---|
| 源码与配置 | API／数据库／云服务凭证、私钥、签名证书、Webhook、带认证 URL、内网地址、生产默认口令；`.env.example` 也可能误放真实值 |
| 文档与 Agent 材料 | README、CURRENT_PROGRESS、AGENTS、DESIGN、.context、prompt、工作日志、会话导出；个人经历、实习／公司内部信息、服务器、绝对路径与未公开仓库链接 |
| 数据与测试 | 真实题库、个人笔记、简历、面试记录、学习历史、用户上传、SQLite／备份／dump、测试快照；“测试数据”不是虚构数据的证明 |
| Git 范围 | 所有拟公开远端分支／标签的历史文件与消息、旧文件名、作者与邮箱、签名和标签消息；明确浅克隆及缺失 refs |
| 其他存储 | LFS 真实对象与历史、子模块 URL／内容归属、gitlinks；只扫描指针文件不算检查实际资产 |
| 发布清单 | 当前跟踪、已暂存、拟新增、打包包含内容分别核对；ignore／.gitattributes export-ignore 不删除历史，也不自动控制所有构建器 |

路径、文件名、账号和邮箱结合语境判断。GitHub noreply、公开昵称、开源作者版权署名、说明用的 localhost 不自动视为应删除；真实联系方式或身份信息按本人公开意愿判断。

## 图片、视频与文档

- README 图、旧 refs 里的图、Release 附件和远端评论附件分开列清单。历史媒体很多时可选择不公开旧历史；未检查旧媒体不能将原仓库标 READY。
- 逐张看拟公开截图：侧栏、浏览器标签、地址栏／查询参数、通知、头像、用户名、邮箱、真实文档标题、学习数据、聊天、二维码、后台路径及终端输出。
- 视频不仅看封面：可见帧／字幕与音轨均可能泄露；抽样时写明覆盖区间，不能宣称逐帧全查。无法覆盖时先不发该资产。
- EXIF／XMP／GPS／作者／设备／创建软件等元数据按授权本地检查。看起来没隐私不等于无元数据；工具不支持时保持未查。
- PDF／Office 检查作者属性、批注、修订、隐藏工作表／页、附件／嵌入对象及可恢复文字。图片上的遮挡不等于底层文本已移除。
- 优先重新生成虚构演示，导出扁平图片并回看，不把含原文的可编辑源文件一起发布。保留原件，不未经授权覆盖或删除。
- 不为了识别图片把真实内容交给外部 OCR／在线工具。OCR 只补充文字检出，不能代替视觉核对。

## 包与构建输出

- 发布的是 ZIP／JAR／Wheel／npm 包／App／DMG 时，检查最终包而非只看源码或构建脚本。先只读列内容，再按授权在隔离目录解包；防止路径穿越、符号链接逃逸和解压炸弹，不运行未知二进制／安装脚本。
- 关注 `.git`、环境文件、数据库、logs、用户缓存、备份、真实样例、内部文档、sourcemap、调试符号、源码嵌入的本机路径、打包器自动收集的资源。
- Python／Node／JVM／原生应用均可能嵌入字符串或本机路径；必要时使用可用静态分析工具。没有相应检查能力就明确限制，不自动安装工具。
- 包内运行时、字体、图标、图片、音乐、模型权重及第三方二进制分别核对再分发条件和必要 NOTICE／LICENSE。本人写了代码不等于拥有全部素材版权。
- 保留实际平台、架构、签名／公证、网络请求及运行时依赖边界；不把 arm64 本机验证写成所有 Mac／平台通过。
- 临时 staging、扫描报告、恢复映射和内部证据不进入包；发布前 hash 绑定已检查资产。

## GitHub 与发布链路

只有被授权的远端范围才读取；不打印 Secret 值，也不扩展到关联私有仓库或组织。

- 仓库 issues／PR 的正文、评论、附件、旧 diff／refs；Wiki、Releases（旧资产也包括）、自动源码归档、LFS、Pages 与 Packages 分别覆盖。删除最新文件不影响这些独立载体。
- Actions 历史／日志／artifacts 可能含内部路径、环境输出和资料；缓存与外部 artifact 存储按实际访问机制检查，不笼统声称所有缓存必然匿名可见。公开前重新核对 GitHub 官方规则。
- 检查工作流触发条件、默认 GITHUB_TOKEN 权限、fork PR、不可信输入、`pull_request_target`、自托管 runner、自动 Pages／Release／包发布、第三方 Action 与凭证使用方式。不要让“不可信 PR 代码＋有权限环境”组合变成攻击入口；这是发布相关检查，不自动升级为全应用渗透测试。
- 公开仓库可能改变 rulesets、安全功能、fork 网络与组织策略。记录相关保护现状及需要复核的变化；不假设“保留同名仓库就保留全部保护”。不擅自改设置。
- GitHub Secret scanning／Push protection 是补充，覆盖受平台支持与配置影响；它们不是截图、个人资料或版权审查。
- 已公开的信息可能被 fork、clone、搜索或缓存；改回 Private 不能收回副本。需要清理已有泄露时先处置凭证风险，再按 GitHub 指南核对历史、PR、缓存与副本残留。

## 开源完整性与最小可用性

- 确认有权发布：雇主／客户代码、课程合作、第三方题库、文章、API 示例、歌曲图片和截图内容的版权边界。归属不明确先剔除或 HOLD，不默认全部套 MIT。
- 项目 LICENSE 与包元数据一致；保留第三方许可证、版权和 NOTICE。无许可证可讨论为“源码公开”，不宣称有可再利用的开源许可。
- 新用户用 README 找得到下载／启动入口，虚构示例与配置模板够用，不依赖私人文件或硬编码本机路径。按已授权范围运行隔离验证，不为验收读取真实数据库。
- 发布前检查仓库／候选／资产无漂移；公开后核对实际 visibility、HEAD／refs、资产 hash 和可访问性，区分发布完成与用户验收。
